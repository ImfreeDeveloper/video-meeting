# Plan: User Profile & Edit Profile Page

**PRD:** docs/prd-user-profile-and-edit-profile-page.md
**Дата:** 2026-09-22

## Фазы реализации

### Фаза 1: Backend — профиль пользователя: чтение и имя (tracer bullet)

**Цель:** Минимальный рабочий путь: через API можно получить данные текущего пользователя и изменить его имя.
**Затрагивает:** backend, database
**Задачи:**

- [ ] Написать e2e тесты на критерии готовности фазы (`GET /users/me` без токена -> 401; с токеном -> возвращает id/email/name/avatarUrl; `PATCH` имени -> валидация пустого/некорректного имени, успешное обновление, нельзя изменить чужого пользователя) — заведомо red до реализации
- [ ] Добавить поля `name` и `avatarUrl` (nullable) в модель `User` (`apps/api/prisma/schema.prisma`), создать Prisma-миграцию
- [ ] Query `FindUserByIdQuery`/handler в модуле `users`
- [ ] Command `UpdateUserNameCommand`/handler в модуле `users` (валидация непустого имени, обновление только владельца токена)
- [ ] `GET /users/me` и `PATCH /users/me` (имя) за `JwtAuthGuard`, DTO валидации имени

**Когда готово:** e2e тесты фазы зелёные. Авторизованный пользователь получает свои данные (id, email, name, avatarUrl) через `GET /users/me`; может изменить имя через `PATCH /users/me`; неавторизованный запрос отклоняется 401; пустое/некорректное имя отклоняется с понятной ошибкой.

### Фаза 2: Backend — аватар: загрузка, хранение, отдача

**Цель:** Пользователь может загрузить или заменить аватар через API; файл хранится на диске api и отдаётся без JWT-токена (для `<img src>`).
**Затрагивает:** backend
**Задачи:**

- [ ] Написать e2e тесты на критерии готовности фазы (успешная загрузка jpg/png/webp, отклонение недопустимого формата и превышения размера, замена аватара удаляет старый файл с диска, публичная отдача аватара без токена, 404 для отсутствующего аватара) — заведомо red до реализации
- [ ] Конфиг хранения аватаров (allowlist jpg/png/webp, лимит размера через env, отдельная директория хранения) по аналогии с `apps/api/src/meeting-file/config/file-upload.config.ts`
- [ ] `UploadAvatarCommand`/handler: сохранение файла на диск, удаление предыдущего файла аватара пользователя при замене, обновление `avatarUrl`
- [ ] `POST /users/me/avatar` (multipart) за `JwtAuthGuard`
- [ ] Публичный `GET`-эндпоинт отдачи файла аватара по пользователю/имени файла, без `JwtAuthGuard`

**Когда готово:** e2e тесты фазы зелёные. Пользователь загружает/заменяет аватар поддерживаемого формата и размера через API; недопустимый формат или превышение размера отклоняются с понятной ошибкой; при замене старый файл аватара удаляется с диска; аватар доступен по публичному URL без токена; запрос аватара, которого нет, возвращает 404.

### Фаза 3: Backend — смена пароля

**Цель:** Пользователь может сменить пароль, указав старый пароль для подтверждения.
**Затрагивает:** backend
**Задачи:**

- [ ] Написать e2e тесты на критерии готовности фазы (неверный старый пароль -> ошибка, пароль не меняется; верный старый пароль -> пароль меняется; логин новым паролем успешен, старым — отклоняется) — заведомо red до реализации
- [ ] DTO смены пароля (`oldPassword`, `newPassword`, минимальная длина по аналогии с `register.dto.ts`)
- [ ] `ChangePasswordCommand`/handler: сверка старого пароля через `bcryptjs`, хеширование и сохранение нового при совпадении
- [ ] `PATCH /users/me/password` за `JwtAuthGuard`

**Когда готово:** e2e тесты фазы зелёные. Смена пароля происходит только при верном старом пароле, иначе — понятная ошибка и пароль не меняется; после успешной смены пользователь логинится новым паролем, а старый пароль больше не подходит.

### Фаза 4: Frontend — страница профиля: имя и пароль

**Цель:** Пользователь видит свой профиль (email, имя) и может изменить имя и сменить пароль через UI.
**Затрагивает:** frontend
**Задачи:**

- [ ] Спланировать и провести ручную проверку в браузере по критериям готовности фазы (в `apps/web` нет тестовой инфраструктуры — см. `apps/web/CLAUDE.md`): auth-gate на `/profile`, редактирование имени (успех/ошибка валидации), смена пароля (успех/неверный старый пароль)
- [ ] `users-api.ts`: `fetchCurrentUser`, `updateUserName`, `changePassword`, `UsersApiError extends ApiError`
- [ ] Роут `/profile` (`layout.tsx` + `page.tsx`), auth-gate по паттерну `page.tsx`/`session.ts` (редирект на `/login` для неавторизованных)
- [ ] Форма редактирования имени с состояниями сохранения/ошибки/успеха
- [ ] Форма смены пароля (старый/новый/подтверждение нового) с клиентской проверкой совпадения и состояниями ошибки/успеха

**Когда готово:** Страница `/profile` открывается только у авторизованного пользователя (иначе редирект на `/login`); отображает текущее имя и email; позволяет изменить имя и сменить пароль с понятными состояниями ошибки/успеха; проверено вручную в браузере на десктопной и мобильной ширине (~390px); пройден `ui-ux-pro-max`.

### Фаза 5: Frontend — аватар в профиле и на главной странице

**Цель:** Пользователь может загрузить/заменить аватар; имя и аватар отображаются в профиле и в шапке главной страницы без повторного логина.
**Затрагивает:** frontend
**Задачи:**

- [ ] Спланировать и провести ручную проверку в браузере по критериям готовности фазы (загрузка/замена аватара, заглушка без аватара, обновление шапки главной страницы без релогина, переход в профиль из шапки)
- [ ] `uploadAvatar` в `users-api.ts` (multipart, по паттерну `meeting-file-api.ts`)
- [ ] Блок загрузки аватара на `/profile`: скрытый `<input type="file">` + `ref` + HeroUI `Button` (без `react-aria-components` `FileTrigger`), текущий аватар или заглушка-инициалы при отсутствии
- [ ] Обновление локального состояния сессии (`session.ts`) именем и `avatarUrl` после сохранения на `/profile`, без повторного логина
- [ ] Шапка главной страницы (`/`): аватар (или заглушка-инициалы) и имя вместо email, переход на `/profile`

**Когда готово:** Пользователь загружает/заменяет аватар на `/profile`, видит понятную ошибку на недопустимый формат/размер; при отсутствии аватара видна заглушка (инициалы) и на `/profile`, и в шапке `/`; после сохранения имени/аватара на `/profile` шапка `/` обновляется без повторного входа; из шапки `/` есть переход на `/profile`; проверено вручную в браузере на десктопной и мобильной ширине; пройден `ui-ux-pro-max`.
