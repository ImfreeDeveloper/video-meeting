# Plan: Meeting File Upload, Storage, and Display

**PRD:** docs/prd-meeting-file-upload-storage-and-display.md
**Дата:** 2026-09-18

## Фазы реализации

### Фаза 1: Backend — загрузка и хранение файла (tracer bullet)

**Цель:** Минимальный рабочий путь: файл можно загрузить через API, он сохраняется на диске, метаданные — в БД, привязаны к встрече.
**Затрагивает:** backend, database
**Задачи:**

- [ ] Написать e2e тесты на критерии готовности фазы (успешная загрузка, отклонение по формату, отклонение по размеру, отклонение чужой встречи) — заведомо red до реализации
- [ ] Модель/миграция Prisma для метаданных файла (id, meetingId, имя, MIME-тип, размер, путь хранения, дата загрузки, кто загрузил)
- [ ] `POST` эндпоинт загрузки файла на встречу (привязка по `meetingId`, `JwtAuthGuard`, сверка `ownerId` встречи с текущим пользователем)
- [ ] Валидация MIME-типа (аудио: mp3, wav, m4a; видео: mp4, mov; документы: pdf, docx, txt) и максимального размера файла до записи на диск, отклонение с понятной ошибкой при нарушении
- [ ] Сохранение файла на локальный диск api и запись метаданных в БД

**Когда готово:** e2e тесты фазы зелёные. Через API можно загрузить файл поддерживаемого типа на существующую встречу; файл появляется на диске и в БД с привязкой к `meetingId`; загрузка недопустимого формата или превышающего размер файла отклоняется без записи на диск; загрузка на чужую встречу отклоняется.

### Фаза 2: Backend — список, скачивание и удаление файлов

**Цель:** Полный CRUD файлов встречи на уровне API.
**Затрагивает:** backend
**Задачи:**

- [ ] Написать e2e тесты на критерии готовности фазы (список файлов, скачивание, удаление, отказ доступа к чужим файлам) — заведомо red до реализации
- [ ] `GET` эндпоинт списка файлов встречи (только владелец встречи)
- [ ] `GET` эндпоинт скачивания/получения конкретного файла по id (только владелец встречи)
- [ ] `DELETE` эндпоинт удаления файла со встречи (только владелец встречи): удаление с диска и из БД

**Когда готово:** e2e тесты фазы зелёные. Владелец встречи может через API получить список файлов, скачать конкретный файл и удалить его (после удаления файл недоступен по прежней ссылке); запросы к файлам чужой встречи отклоняются.

### Фаза 3: Frontend — загрузка файла и отображение списка

**Цель:** Пользователь может загрузить файл со страницы встречи и видит список уже прикреплённых файлов.
**Затрагивает:** frontend
**Задачи:**

- [ ] Написать e2e тесты (UI) на критерии готовности фазы (успешная загрузка через интерфейс, отображение списка файлов, ошибки формата/размера/сети) — заведомо red до реализации
- [ ] Блок загрузки файла на странице встречи: выбор файла + индикатор прогресса/статуса загрузки
- [ ] Отображение состояний ошибки загрузки (неверный формат, превышен размер, ошибка сети) в интерфейсе
- [ ] Список прикреплённых файлов встречи: имя, тип, размер, дата загрузки

**Когда готово:** e2e тесты фазы зелёные. Пользователь на странице встречи может выбрать и загрузить файл поддерживаемого формата, видит прогресс/результат загрузки и понятную ошибку при неверном формате/размере/сети; список файлов встречи отображается с именем, типом, размером и датой.

### Фаза 4: Frontend — скачивание и удаление файла

**Цель:** Пользователь может скачать или удалить прикреплённый файл прямо со страницы встречи.
**Затрагивает:** frontend
**Задачи:**

- [ ] Написать e2e тесты (UI) на критерии готовности фазы (скачивание файла, удаление файла и его исчезновение из списка) — заведомо red до реализации
- [ ] Действие "скачать" для файла в списке (скачивание/открытие файла)
- [ ] Действие "удалить" для файла в списке (файл исчезает из списка после удаления)

**Когда готово:** e2e тесты фазы зелёные. Пользователь может скачать любой файл из списка и удалить его; после удаления файл пропадает из списка и недоступен по прежней ссылке.
