# PRD: User Profile & Edit Profile Page

**Дата**: 2026-09-22
**Статус**: Draft

## Цель

Дать пользователю страницу профиля и возможность отредактировать свои данные — имя, аватар и пароль, — а также показывать имя и аватар текущего пользователя на главной странице, чтобы было понятно, под каким аккаунтом выполнен вход.

## Пользовательский сценарии

- Пользователь открывает страницу профиля -> видит текущий аватар, имя и email.
- Пользователь на странице профиля меняет имя и сохраняет -> новое имя отображается в профиле и в шапке главной страницы.
- Пользователь загружает новое изображение как аватар -> аватар обновляется в профиле и в шапке главной страницы.
- Пользователь вводит текущий пароль и новый пароль и сохраняет -> пароль меняется, пользователь может войти новым паролем.
- Пользователь вводит неверный текущий пароль при смене пароля -> видит понятную ошибку, пароль не меняется.
- Пользователь пытается загрузить аватар недопустимого формата или превышающий лимит размера -> видит понятную ошибку, аватар не сохраняется.
- Пользователь без загруженного аватара открывает профиль или главную страницу -> видит заглушку аватара (например, инициалы).
- Пользователь заходит на страницу профиля не будучи авторизованным -> перенаправляется на страницу входа (как остальные защищённые страницы).

## В скоупе

- Поле `name` (имя пользователя) на модели User; заполняется/редактируется через профиль (при регистрации сейчас нет ввода имени — до первого редактирования профиль показывает email или заглушку вместо имени).
- Поле `avatarUrl` (или аналог) на модели User для хранения ссылки/пути на загруженный аватар.
- Эндпоинт получения данных текущего пользователя (`GET`, по токену из `JwtAuthGuard`) — имя, email, ссылка на аватар.
- Эндпоинт обновления имени пользователя (`PATCH`/`PUT`), доступен только самому пользователю (из токена).
- Эндпоинт загрузки/замены аватара (`POST`/`PUT`, multipart) — принимает изображение, сохраняет на диске сервера api (по аналогии с хранением файлов встреч), обновляет `avatarUrl`; предыдущий файл аватара удаляется с диска при замене.
- Ограничение на допустимые форматы изображения (jpg, png, webp) и максимальный размер файла аватара, с отклонением загрузки при нарушении.
- Эндпоинт смены пароля — принимает старый и новый пароль, проверяет старый пароль перед сохранением нового; при несовпадении — ошибка, пароль не меняется.
- Страница `/profile` (web): отображение текущего имени, email и аватара; форма редактирования имени; форма загрузки/замены аватара; форма смены пароля (старый пароль + новый пароль + подтверждение нового пароля).
- Отображение состояний ошибок (неверный формат/размер аватара, неверный старый пароль, ошибка сети) и состояния успешного сохранения на странице профиля.
- Отображение имени и аватара текущего пользователя в шапке главной страницы (`/`), на месте текущего отображения email — с заглушкой аватара, если он не загружен.
- Ссылка/переход на страницу профиля из главной страницы (например, по клику на блок с именем/аватаром пользователя в шапке).

## Не в скоупе

- Смена email пользователя.
- Удаление аккаунта.
- Двухфакторная аутентификация или подтверждение email/пароля через письмо.
- Восстановление пароля без знания старого (flow "забыл пароль").
- Обрезка/редактирование изображения аватара в браузере (кроп, поворот) — принимается изображение как есть, без клиентского редактирования.
- Просмотр профилей других пользователей.
- История изменений профиля / аудит-лог.
- Внешние объектные хранилища (S3 и аналоги) для аватаров — используется локальный диск сервера api, как и для файлов встреч.

## Технические ограничения

- Модель `User` в `apps/api/prisma/schema.prisma` сейчас не имеет полей `name` и `avatarUrl` — требуется миграция Prisma.
- Хранение аватаров на диске api-сервера следует по аналогии с `apps/api/src/meeting-file` (allowlist по расширению+MIME, лимит размера через env, отдельная директория хранения) — отдельный модуль/путь хранения, не переиспользующий директорию `meeting-file`.
- Отдача аватара пользователю (в т.ч. на главной странице другого клиента/устройства) должна работать без необходимости передавать `Authorization`-заголовок на `<img src>` — т.е. либо публично доступный статический путь, либо отдельный не защищённый JWT-guard'ом эндпоинт отдачи файла (в отличие от скачивания файлов встреч, которое сейчас идёт через `fetch` с токеном).
- Смена пароля переиспользует существующую логику хеширования (`bcryptjs`), используемую в `auth`/`users` модулях.
- `web`: файл выбирается через скрытый `<input type="file">` + `ref`, по паттерну из `meeting/[id]/page.tsx`, а не через `react-aria-components` `FileTrigger` (известная проблема резолва peer-зависимости в pnpm-сетапе этого репозитория).
- Данные текущего пользователя (имя, аватар) на главной странице должны обновляться после сохранения на странице профиля без необходимости повторного логина (обновление локального состояния сессии/кэша на клиенте).

## Критерии готовности

- [ ] На модели `User` есть поля `name` и `avatarUrl`, применена миграция Prisma.
- [ ] Эндпоинт `GET` текущего пользователя возвращает имя, email и ссылку на аватар для авторизованного запроса и 401 для неавторизованного.
- [ ] Эндпоинт обновления имени сохраняет новое имя только для владельца токена и возвращает ошибку валидации на пустое/некорректное имя.
- [ ] Эндпоинт загрузки аватара принимает jpg/png/webp в пределах лимита размера, отклоняет остальные форматы и файлы сверх лимита с понятной ошибкой.
- [ ] Загрузка нового аватара удаляет с диска файл предыдущего аватара того же пользователя.
- [ ] Эндпоинт смены пароля меняет пароль только при верном старом пароле; при неверном — возвращает ошибку и пароль не меняется.
- [ ] После смены пароля пользователь может войти новым паролем, а старый пароль больше не подходит.
- [ ] Страница `/profile` доступна только авторизованному пользователю, неавторизованный перенаправляется на `/login`.
- [ ] На странице `/profile` можно изменить имя, загрузить/заменить аватар и сменить пароль; каждое действие показывает состояние успеха или понятную ошибку.
- [ ] Изменённое имя и аватар отображаются в шапке главной страницы (`/`) без повторного логина.
- [ ] Пользователь без загруженного аватара видит заглушку (например, инициалы) и в профиле, и в шапке главной страницы.
- [ ] Из шапки главной страницы есть переход на страницу профиля.
